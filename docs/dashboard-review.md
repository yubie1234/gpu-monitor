# 대시보드 사용자 리뷰 & 개선 (develop 기준)

> 관점: **일반 사용자**가 `MONITOR_DEMO=true` 로 대시보드(`/`)를 직접 써 보고 정리.
> 범위: 프론트엔드(`app/web/templates/dashboard.html`)만. 수집/집계 로직·할당(allocation)
> 경계는 건드리지 않는다(실사용률 아님).

## 정리

### 🐞 버그

| # | 내용 | 상태 |
|---|---|---|
| B1 | 잘린 텍스트에 tooltip 없음 — 네임스페이스 랭킹(`kser…`), 파티션 프로파일(`1g.1…`), 긴 노드명은 전체 이름을 볼 방법이 아예 없었다. | ✅ 수정 |
| B2 | 긴 노드명이 카드 밖으로 넘칠 수 있음(`.nname` 에 ellipsis 없음). | ✅ 수정 |
| B3 | auto-refresh 를 껐다 다시 켜도 즉시 갱신 안 되고 `interval`(기본 수 초) 만큼 대기. | ✅ 수정 |
| B4 | 연결 실패 시 마지막 데이터가 그대로 남고 표시등만 빨강 — 데이터가 얼마나 오래됐는지(stale) 알 수 없었다. | ✅ 수정 |

### 😕 불편한 부분

| # | 내용 | 상태 |
|---|---|---|
| U1 | 노드/워크로드 **검색·필터 없음** — 노드가 많아지면 스크롤 벽. 특정 pod/네임스페이스/제품을 찾기 어렵다. | ✅ 개선 |
| U2 | 갱신 시각이 **절대시각만** — "몇 초 전"인지, 데이터가 신선한지 직관적으로 안 보인다. | ✅ 개선 |
| U3 | NotReady/수집 에러가 **상단에 요약되지 않음** — 문제 있는 워크로드를 찾으려면 모든 카드를 스캔해야 한다. | ✅ 개선 |
| U4 | 노드 **정렬 옵션 없음**(이름순 고정) — "가장 꽉 찬 노드"/"여유 있는 노드"를 못 찾는다. | ✅ 개선 |

### ✨ 추가되면 좋은 기능(구현)

- **검색 바** — 노드명·제품·워크로드명·타입·네임스페이스·purpose·environment·pod 를 가로질러 필터. 공유(TS/MPS/MIG) 풀 안의 워크로드도 검색 대상.
- **정렬** — 이름순 / 할당률 높은순 / 유휴 많은순. 동률은 이름순으로 안정 정렬.
- **상대 시각 + stale 경고** — "N초 전"으로 표시하고, 갱신이 주기의 2.5배+여유를 넘기거나 연결이 끊기면 경고색. 절대 시각은 hover(title)로.
- **문제 요약 칩** — `NotReady 노드/워크로드 · 수집 에러` 개수를 상단에 표기. 클릭하면 문제 있는 노드만 필터(토글). 이상 없으면 `✓ 이상 없음`.
- 검색/정렬은 **재-fetch 없이** 보관된 스냅샷(`LAST`)으로 노드 카드만 다시 그린다.

## 남은(미구현) 아이디어

- 범례/랭킹 항목 클릭 → 해당 워크로드 타입·네임스페이스로 노드 필터 연동.
- 필터 상태를 URL query 로 보존(공유/새로고침 유지).
- 라이트 테마 토글(현재 다크 전용).
